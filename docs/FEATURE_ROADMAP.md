## Cross-cutting requirements (every item)

- Works in API mode and static (Pages) mode.
- Extends `verify-db.ts` for any new table.
- User-facing text (UI, feeds, notifications) passes the banned-phrase test.
- Estimates are labeled; models show sample size and range.
- Rejected framings stay rejected: hot/cold, "win more", affiliate links.

## How to maintain this file

When a feature ships, set its backlog status to `Shipped (<commit>)` and remove it from the tables above. Add it to FEATURE_RESEARCH §2. When scores change, re-run the scoring script (FEATURE_RESEARCH §22) and re-order here.
